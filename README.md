# CLASP

**Classroom Language Activities and Simulation Platform** — локальная учебная среда для занятий английским языком в ИТ-аудитории.

Первый MVP: преподаватель показывает экран или окно; студенты смотрят в браузере и получают карточки материалов и заданий. Студенты могут отправлять и обновлять текстовые ответы. Преподаватель видит ответы, студенты — только собственные. Конспект выгружается в TXT.

## Как устроена трансляция

Браузер преподавателя захватывает выбранный экран через Screen Capture API и публикует один видеопоток WebRTC в локальный LiveKit SFU. SFU пересылает поток студентам без создания JPEG/PNG, без перекодирования и без записи видео. Simulcast отключён. Настройка захвата: до 1920×1080, 15 кадров/с, целевой предел 4 Мбит/с. Фактические параметры зависят от браузера, окна и сети.

Права ограничены сервером: преподаватель может публиковать только screen_share; студент имеет только подписку и не может публиковать ни видео, ни звук, ни сообщения LiveKit. Карточки и ответы передаются отдельно через HTTP + Server-Sent Events. Карточки сохраняются на сервере и доступны подключившимся позже.

Первоначальная загрузка пакетов и Docker-образов требует интернета. После подготовки сервисы предназначены для работы в одной локальной сети; внешние облачные сервисы, CDN и TURN не используются. Работу полностью без интернета ещё нужно подтвердить натурным испытанием.

## Запуск в аудитории (Windows / Linux)

Нужны Node.js 22+ и Docker с Compose (на Windows — Docker Desktop). На компьютере преподавателя или выделенном сервере:

```sh
git clone https://github.com/Moonkeeper-hub/CLASP.git
cd CLASP
node scripts/setup.mjs 192.168.1.50
docker compose up -d --build
```

Замените `192.168.1.50` на IPv4 компьютера-сервера в сети аудитории. Желательно закрепить его DHCP-резервацией. Скрипт создаёт локальные настройки и случайные ключи. Повторный запуск не перезаписывает существующие ключи. В `.env` находится `TEACHER_KEY` для преподавателя. Этот файл и `config/livekit.yaml` нельзя передавать студентам или коммитить.

Разрешите входящие соединения от компьютеров аудитории: **TCP 443**, **TCP 7881**, **UDP 7882**. Между устройствами должна быть разрешена связь: изоляция Wi-Fi-клиентов помешает трансляции. Контейнеры app и LiveKit API не публикуют свои HTTP-порты наружу.

### HTTPS — обязательная однократная настройка

Caddy создаёт локальный центр сертификации. Корневой сертификат нужно извлечь:

```sh
docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt ./clasp-root.crt
```

Установите **только этот публичный корневой сертификат** в доверенные корневые центры сертификации на компьютере преподавателя и всех компьютерах студентов. На Windows: открыть файл → «Установить сертификат» → «Текущий пользователь» → выбрать хранилище «Доверенные корневые центры сертификации». В управляемой аудитории установку может выполнить администратор централизованно. Некоторые браузеры имеют собственное хранилище; начните с Chrome или Edge.

Не копируйте приватные ключи Caddy. Перезапустите браузеры после установки. Адрес `https://192.168.1.50` должен открываться без предупреждений. Простого обхода предупреждения сертификата недостаточно для надёжной работы защищённого WebSocket и Screen Capture API. Удаление Docker-тома caddy_data потребует повторной установки нового корневого сертификата.

### Занятие

1. Преподаватель открывает HTTPS-адрес, раскрывает «Вход преподавателя», вводит название и TEACHER_KEY.
2. Сохраняет ID занятия, чтобы продолжить его позже. Для продолжения вводит ключ и этот ID.
3. Сообщает студентам адрес страницы и восьмизначный код занятия.
4. После подключения трансляции нажимает «Показать экран», выбирает экран, окно или вкладку в диалоге браузера.
5. Отправляет карточки типа «Материал» или «Задание с ответом». Студенты отвечают в карточке; преподаватель видит ответы под заданием.
6. Кнопка «Сохранить» выгружает материалы и видимые пользователю ответы в текстовый конспект.

Звук, камера и студенческая демонстрация в этом MVP отключены. Запуск захвата всегда требует явного выбора преподавателя в браузере. Для видео с высокой частотой кадров текущий профиль не предназначен.

## Данные и ограничения первого среза

- Карточки и ответы сохраняются в Docker-томе classroom_data, в одном JSON-файле с атомарной заменой. Один экземпляр приложения, до 300 карточек на занятие. Не запускайте несколько реплик с этим хранилищем.
- Сессии действуют до 12 часов и живут в памяти. Обновление вкладки сохраняет сессию через sessionStorage. После перезапуска сервера или нового входа студент получает новую личность; старые ответы остаются у преподавателя, но автоматически не привязываются к новому входу. Постоянных аккаунтов пока нет.
- Код занятия не истекает автоматически. Нет завершения/удаления занятия и ротации кода в интерфейсе. MVP предназначен для доверенной локальной аудитории, без публикации в интернет.
- Доступ к материалам не требует доступности медиасервера. При ошибке трансляции карточки продолжают работать.
- Нагрузка сети сервера растёт с числом зрителей: 25 × 4 Мбит/с ≈ 100 Мбит/с только на исходящий видеопоток. Это оценка, не результат нагрузочного теста. Для сервера предпочтительно гигабитное проводное подключение.
- Изображения и вложения в карточках, проверка/оценивание ответов, сценарии issue/PR/chat и постоянные аккаунты — следующие этапы.

## Разработка и проверка

```sh
npm ci
npm test
npm run build
npm start
```

Для npm start нужен `.env`, созданный setup. Он поднимает только приложение на HTTP-порту 3000: для LAN-трансляции используйте весь HTTPS-стек Compose. Браузерный SDK собирается локально; обращения к CDN во время занятия нет.

Автотест проверяет вход, серверные права ролей в JWT, live-доставку карточки по SSE, изоляцию ответов, подключение опоздавшего и сохранность после перезапуска приложения. Он не подменяет испытание настоящего WebRTC.

### Приёмка в локальной сети

- Два отдельных компьютера: преподаватель выбирает окно, студент видит его изменения, разворачивает трансляцию, получает карточку и отправляет ответ.
- Запоздалый вход: появляются ранее отправленные материалы и текущая трансляция.
- Остановка и новый запуск показа, закрытие окна демонстрации, обновление студенческой вкладки.
- Краткое отключение сети: восстановление трансляции и карточек без потери черновика в открытой вкладке.
- Проверка с реальным числом студентов, замер задержки, битрейта, загрузки CPU и сети; затем повтор с отключённым интернетом.

На момент начального коммита проверены API и сборка. Запуск Chromium в среде разработки заблокирован ограничениями среды, поэтому интерфейс в настоящем браузере, Docker Compose и передача экрана между физическими устройствами в аудитории ещё не проверены.

## Основные файлы

- `server.js`: HTTP API, выдача прав LiveKit, карточки, ответы и SSE.
- `public/`: интерфейс преподавателя и студента.
- `scripts/setup.mjs`: генерация настроек локального запуска.
- `compose.yaml`, `Dockerfile`: приложение, LiveKit и HTTPS-прокси.
- `test/server.test.js`: интеграционный тест API.

Технические источники: [Screen Capture API](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia), [LiveKit screen sharing](https://docs.livekit.io/transport/media/screenshare/), [права участников](https://docs.livekit.io/frontends/reference/tokens-grants/), [порты LiveKit](https://docs.livekit.io/transport/self-hosting/ports-firewall/).
